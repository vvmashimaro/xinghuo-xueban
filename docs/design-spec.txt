为了将“星火学伴”从分散的页面演化为一套**逻辑自洽、架构严密、各角色业务闭环**的商业级系统，我们需要对当前的前端架构与商业闭环进行系统化重构。

以下是全站的**系统逻辑全景梳理**与**全站统一设计架构框架**。

---

## 一、 系统全链路业务逻辑梳理

平台依托“**阳光撮合 + IoT智能硬件 + 银行智能合约托管**”构建闭环，打破传统教培的“重资产、大额预付、涉嫌地下私教违规”三重泥潭：

```
[角色端]                      [平台核心枢纽]                       [履约与风控结算]
                             
导师端 (大学生) ────┐                                             ┌─── IoT智能隔音教学仓
                   ├──> 【身份安全网】 ──> 【智能调度引擎】 ──┤    (扫码通电/20:30强制断电)
家长/学员端 ───────┘    (学信网+公安核验)   (学情标签深度召回)  └─── 商业银行托管账户
                                                                     (一课一消/双向核销秒结)
                                     ▲
                                     │
                        管理审核端 (L1/L2教研风控)

```

### 1. 角色交互生命周期矩阵

| 业务环节 | 导师端 (`index.html`) | 家长/学员端 (`parent_dashboard.html`) | 管理风控端 (`admin_audit.html`) |
| --- | --- | --- | --- |
| **01. 准入与建档** | **L1资质认证**：公安实人+学信网报告解析+非在编公立教师承诺；填写入款银行卡。 | **学情画像建档**：输入年级、考纲薄弱考点、教学进度诉求（查缺补漏/培优拔高）。 | 队列接收待审申请，查验学历底库一致性、工作单位与红线承诺。 |
| **02. 评级与画像** | **L2专长标签**：录播5-10分钟试讲视频、勾选学科（小学/初中/高中/考研/特色艺考）、时薪阶梯建议评估。 | **AI算力匹配**：基于学员薄弱考点、期望时薪与就近物理网点（如成都金沙仓、望江仓），推荐契合度 > 95% 导师。 | 调阅试讲视频并对板书规范、解题启发性量规打分；核发电子工牌。 |
| **03. 约课与锁资** | 接单确认：收到系统派单通知，系统锁定授课日程与专属教学仓。 | **一课一消存管**：单次课程资金存入商业银行托管子账户锁定；**无大额预付费**。 | 交易资金全程受监管行监控，平台不设资金池。 |
| **04. 线下空间履约** | 凭动态二维码进出教学仓；联动通电、通风、照明；20:30触发系统断电。 | 双向扫码核验确认完课；遇纠纷2小时冷静期支持系统介入。 | 异常停留与超时报警接入AI云巡检平台。 |
| **05. 结算与沉淀** | 资金秒级划拨（92%归导师，8%平台运营维护费）；累积官方实习学时与评价。 | 记录学员课堂错题与考点消化情况，更新学情护照雷达图。 | 沉淀师资履约信用分体系，异常跳单/低星导师降权或下架。 |

## 二、 全站统一设计系统规范 (Design System Tokens)

为了保证全站各终端在视觉感知与交互手感上的一致性，确立以下设计规范：

```
+-----------------------------------------------------------------------------------+
| 视觉设计原则：                                                                     |
| • 科技向善 (Trust & Tech)：Slate 深板岩灰 + Teal 活力松石绿，传递合规、安全与专注感   |
| • 信息减负 (Clarity)：摒弃繁琐装饰，采用卡片化 (Card-based UI) 与数据可视化胶囊       |
| • 实时反馈 (Reactivity)：表单联动右侧「实时镜像看板」，输入即预览，所见即所得        |
+-----------------------------------------------------------------------------------+

```

### 1. 调色盘规范 (Color Palette)

| 语义层级 | 色值 (HEX / Tailwind) | 应用场景 |
| --- | --- | --- |
| **主品牌色 (Primary)** | `#0d9488` (`teal-600`) | 主操作按钮、选中状态、品牌标志、重要信息图标 |
| **主品牌暗色 (Primary Dark)** | `#0f766e` (`teal-700`) | 按钮 Hover/Active 态、高亮卡片边框 |
| **品牌底色深色 (Slate Dark)** | `#0f172a` (`slate-900`) | 桌面端深色侧边栏、移动端 Hero Banner 背景、核心标题 |
| **中性文字深 (Text High)** | `#1e293b` (`slate-800`) | 正文、各级标题、表单输入主文本 |
| **中性文字浅 (Text Muted)** | `#64748b` (`slate-500`) | 辅助说明文案、字段提示、占位符 |
| **界面背景底色 (Surface)** | `#f8fafc` (`slate-50`) / `#f1f5f9` (`slate-100`) | 主视窗背景、卡片外衬灰底 |
| **状态色 (Status)** | 绿 `#10b981` / 橙 `#f59e0b` / 红 `#ef4444` | 学信网核验通过、资金托管冻结、违规红线报警 |

### 2. 交互与动效规范 (Interaction Rules)

* **圆角层次**：主容器外框采用 `rounded-2xl` (16px)，内嵌表单组件采用 `rounded-xl` (12px)，标签与徽章采用 `rounded-full`。
* **反馈机制**：全站禁止使用原生浏览器阻塞式的 `alert()`，统一使用浮动式 `showToast()` 动态通知与内嵌模态框。
* **响应式栅格**：
* 移动端（`< 768px`）：单列流式布局，右侧看板收拢到底部抽屉或隐藏；
* 桌面端（`>= 1024px`）：左侧主表单区占 `60%~65%`，右侧粘性定位（`sticky top-20`）看板占 `35%~40%`，保持双目视野无缝核验。

## 三、 全站页面工程拓扑与架构蓝图

当前工程中构建的 5 大前端模块的职责划分与协同调用关系如下：

```
                         ┌────────────────────────┐
                         │   login.html           │
                         │   统一多端身份登录中枢   │
                         └───────────┬────────────┘
                                     │
                 ┌───────────────────┴───────────────────┐
                 ▼                                       ▼
       [青年导师认证通路]                       [家长/学员服务端]
  ┌─────────────────────────┐               ┌─────────────────────────┐
  │ index.html              │               │ parent_register.html    │
  │ 导师认证与动态入库中枢   │               │ 学员注册与考纲建档中心   │
  └────────────┬────────────┘               └────────────┬────────────┘
               │                                         │
               ▼                                         ▼
  ┌─────────────────────────┐               ┌─────────────────────────┐
  │ admin_audit.html        │               │ parent_dashboard.html   │
  │ 管理端综合质审工作台     ├──────────────>│ 家长主控与智能匹配系统   │
  │ (学信网+试讲量规打分)   │ [核验导师数据流]│ (IoT门禁+资金托管约课)   │
  └─────────────────────────┘               └─────────────────────────┘

```

### 各模块职责矩阵：

1. **`login.html`（统一多角色登录中枢）**：
* **输入**：手机号、短信验证码/密码、协议同意状态。
* **路由分发**：根据选定角色分别导流至导师认证体系或家长学员主控中心，底部设置合规入口直达管理端。


2. **`index.html`（导师建库与认证中心）**：
* **L1 模块**：全国院校级联选择、学信网 16 位码模拟直连、非在编承诺一票否决、银行卡号收集。
* **L2 模块**：涵盖“小学-初中-高中-考研-特色自选（艺考等）”五层学段学科，结合时薪难度联动判定、试讲视频提交与证明材料文件流。
* **看板**：家长端展示脱敏（张老师）实时预览名片。


3. **`admin_audit.html`（管理端风控审核工作台）**：
* **审核漏斗**：多状态筛选（待初审/已入库/打回/违规否决），查验学信网报告一致性与三要素账户。
* **教研定级**：调阅试讲视频，基于板书逻辑三维量规打分，一键发放电子工牌与开仓授权码。


4. **`parent_register.html`（学情诊断与注册中心）**：
* **学情护照建档**：年级（小初高）考纲难点细分勾选（如二次函数最值、动态电路分析），四维辅导定位（查缺补漏/提优冲刺）。
* **意向匹配**：就近实体教学仓选择（金沙仓/望江仓/大源仓）与预算区间标定。


5. **`parent_dashboard.html`（家长主控台与智能调度平台）**：
* **智能召回**：顶部自适应算法推荐契合度 > 95% 优选师资。
* **全景筛选**：学科胶囊过滤、时薪区间滑动、试讲视频在线查验播放。
* **交易与硬件闭环**：基于招商银行合约存管完成单次课资金锁定，即时生成 IoT 动态防伪进门二维码与离线口令。

## 四、 核心落地推进与实施计划 (Next Actionable Milestones)

1. **数据层解耦与共享存储（LocalStorage / API Service）**：
* 当前各页面依赖内存与模拟状态运作。下一步应抽象出统一的 `StorageService`（或轻量后端 API），让在 `index.html` 注册的导师真实流转至 `admin_audit.html` 审核，审核通过后即刻展示在 `parent_dashboard.html` 的导师列表中。


2. **IoT 硬件网关模拟（Websocket/MQTT 交互）**：
* 为 `parent_dashboard.html` 增设“开门模拟状态”，模拟家长/导师刷码后，门禁开启、环境灯光接通及倒计时到 20:30 的断电交互演练。


3. **合规协议合同组件（E-Contract）**：
* 在家长约课与资金锁定前，增加《三方托管服务居间协议》在线签署流程，彻底坐实平台的“技术中立撮合与空间运营者”法律定位。
